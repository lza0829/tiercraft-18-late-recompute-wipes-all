# 05-tiercraft（筑层）

筑层 — 数仓分层建设台：贴源入仓 → 明细清洗标准化 → 汇总落表 → 层间行数/键对账。

**不是** 多源 Feed 归并，**不是** 作业依赖编排，**不是** CDC 变更流按序落库，**不是** 质检隔离签发。
**也不是** 报表看板 / CRUD 后台 / 电商订单前台 / OA 工单。

## 启动

```bash
docker compose up --build
```

本地开发：

```bash
# 后端
cd backend
pip install -r requirements.txt
set DATA_DIR=..\data
uvicorn app.main:app --reload --port 10500

# 前端
cd frontend
npm install
npm run dev
```

| 入口 | 地址 |
| --- | --- |
| 前端 | http://localhost:5500 |
| 接口 | http://localhost:10500 |

## 主链

登记主题域 → 贴源层装载夹具 → 明细层清洗标准化 → 汇总层聚合 → 层间对账报告与各层列表数字同源

## 迟到业务日与定点重算

汇总生成后若再追加同一业务日的贴源新行，系统按以下规则处理，无需全量重跑：

1. **迟到标记**：贴源新行的装载时间晚于该业务日最近一次成功明细任务（明细水位线）时，该业务日登记为「待重算」迟到日。从未加工过的业务日只算待加工，不算迟到。标记可在「分层任务」「层间对账」「主题域」与总览视图查询。
2. **定点重算**：仅对受影响业务日，先按现行清洗规则重跑当日明细（其它日明细行不删除、不改写），再只重算当日汇总键；全程不清空明细表或汇总表。
3. **重算报告**：逐业务日列出重算前后明细行数、汇总金额，并校验汇总金额与当日明细金额一致；报告落库，刷新后仍可查询。
4. **标记收敛**：定点重算成功后，迟到日转为「已重算」且记录保留；只重跑汇总而明细未重跑时，迟到标记保持「待重算」。

### 相关接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/layers/paste` | 追加贴源新行，返回是否触发迟到 |
| GET | `/api/late-days` | 查询迟到业务日（可按主题域、状态过滤） |
| POST | `/api/late-days/rescan` | 按贴源装载时间重新扫描迟到日 |
| POST | `/api/jobs/late-recompute` | 定点重算；缺省重算全部待重算迟到日，也可传 `biz_days` 指定 |
| GET | `/api/recompute-jobs` | 定点重算报告（含逐业务日前后行数与金额） |
